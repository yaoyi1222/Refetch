### 7. bench/bench_cache.py + bench/results/v0.3_fastapi.md

`bench_cache.py` (network when run, offline-importable):
- Discover N in-domain URLs via `lightcrawl map` (or a static fallback list).
- **Pass 1** (warm): `batch-fetch --max-age 1h` → stores every body, records each
  envelope (expect `cache_hit=False`).
- **Tier (a)** — immediately repeat `batch-fetch --max-age 1h`; the entries are
  fresh, so report `cache_hit / total` (acceptance ≥ 0.95).
- **Tier (b)** — repeat `batch-fetch --max-age 1ms`: the entries are now "stale"
  for that window but `store_in_cache` keeps the cache in play, so the router
  sends a conditional GET; report `revalidated / total` over URLs that carry a
  validator (acceptance ≥ 0.5). Same conditional path proven by
  `bench/probe_conditional.py` (R1 gate, hit-rate 0.67). A tiny `--max-age`
  stands in for the ">24h, no `--max-age`" crawl scenario without a 24h wait.
- Prints a JSON summary; `--out` writes it under `bench/results/`.

`v0.3_fastapi.md`: the manual end-to-end §10.1 command
(`lightcrawl crawl https://fastapi.tiangolo.com/ --max-pages 200 --max-depth 4`),
the two-tier cache method, and a results table with cells marked
**PENDING (run locally)**. Filled by whoever runs the live benchmark.
