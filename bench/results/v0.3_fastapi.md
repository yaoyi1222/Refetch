# v0.3 acceptance benchmark — fastapi.tiangolo.com

Manual, **network** benchmark for v0.3 acceptance (`docs/v0.3/design.md` §10.1
end-to-end crawl, §10.2 two-tier cache hit-rate). The harness is committed; the
measured cells below are filled by **running it locally** — they are left
`PENDING` here rather than fabricated (honesty contract, `CLAUDE.md`).

## 1. End-to-end crawl (§10.1)

```bash
.venv/bin/lightcrawl crawl https://fastapi.tiangolo.com/ --max-pages 200 --max-depth 4
# then, with the returned <job_id>:
.venv/bin/lightcrawl crawl-status <job_id>
```

Acceptance: completes, 200 pages each with readable markdown and no HTML
residue.

| `pages_fetched` | ~200 | PENDING (run locally) |
| pages with non-empty markdown | all | PENDING |

## 2. Cache hit-rate, two tiers (§10.2)

```bash
.venv/bin/python -m bench.bench_cache \
  --seed https://fastapi.tiangolo.com/ --limit 25 \
  --out bench/results/v0.3_cache.json
```

`bench_cache.py` measures only the public CLI envelope:

- **Tier (a)** — re-fetch within `--max-age 1h`; `cache_hit / total`.
- **Tier (b)** — re-fetch with `--max-age 1ms` (forces staleness while keeping
  the cache in play → conditional GET); `revalidated / with_validator`. Stands
  in for the ">24h, no `--max-age`" crawl scenario without a 24h wait.

| Tier | Target | Measured |
|---|---|---|
| (a) warm `--max-age 1h` — `cache_hit` ratio | ≥ 0.95 | PENDING (run locally) |
| (b) conditional `304` — `revalidated` ratio (over URLs with a validator) | ≥ 0.5 | PENDING |

Tier (b) is gated on PR 3 (merged) + the R1 probe — see
`bench/results/conditional.json` (`bench/probe_conditional.py`), which already
measured a **0.67** 304 hit-rate on the `chrome120` impersonate path.

## 3. Static-resource 304 path (§10.3)

Covered by `bench/probe_conditional.py` (the R1 gate): it fetches validator-
carrying pages twice and asserts the second request takes the 304 path. Re-run:

```bash
.venv/bin/python -m bench.probe_conditional --out bench/results/conditional.json
```

## Notes

- These hit the network and are intentionally **not** part of the offline
  `pytest` suite. Run them on demand to refresh the cells above.
- A clean `--max-pages 200` crawl can take several minutes and is rate-limited
  by the target site; start with a smaller `--max-pages` to smoke the pipeline.
